## Findings

### Major

**P1. A single-file `except` is excluded from the hash but not from rsync.**
`src/units.rs:164` pushes every carve-out as `push_exact(x, true)`, a
directory-only rule (`--exclude=/secret.txt/`). The loose manifest drops the
path anyway (`units/snapshot.rs:74-93`, `is_within`). As a result, a carved-out
*file* is invisible to the table, while rsync carries it and `--delete`s it.
Unsubscribing a file inside a broader subscription is how `except` gets
populated (`subscribe.rs:172-187`), and PLAN allows file subscriptions.
*Reproduced:* subscription `work` with `except = ["work/secret.txt"]`, and
`secret.txt` only on the leaf. A home-side change elsewhere plans `Pull`, and
the rsync diff is `["- secret.txt", "~ notes.txt"]`, with no refusals and not
blocked. In v0.2 a pull deletes the leaf's carved-out file, and a push sends it
to home. Pre-existing (`main:src/units.rs:145`).
*Fix:* push `except` entries with `is_dir = false`. In both engines the
anchored `/x` matches a file or a directory. Keep `true` for repos and
worktrees, which are always directories. Add a file `except` to
`rsync_diff_tests` and a plan test asserting the diff never names it.

### Minor

**P2. A class range that spans `/` matches across components in globset, not
in rsync.** `src/exclude/pattern.rs:156-170` refuses a literal `/` in a class
but accepts ranges such as `[+-0]`, `[.-0]` or `[ -~]`, which include 0x2F.
globset's class matches `/` even with `literal_separator(true)`.
*Reproduced* against openrsync: for `x/a[+-0]b`, ours = `{x/a.b, x/a/b, x/a0b}`
and rsync's = `{x/a.b, x/a0b}`. The walker drops `x/a/b` and rsync moves it, so
guardrail 1 cannot see it. The differential test has no such case. Contrived
patterns, but it breaks the "refused if they'd disagree" contract.
*Fix:* in the range loop, refuse `lo <= b'/' <= hi`. Add one refusal test and
one differential case.

**P3. A root exclude containing `/` is relative to each unit, so what it
protects depends on the subscription split and on where repos sit.**
`units::excludes` (`src/units.rs:149-168`) applies `spec.exclude` relative to
the unit's `rel`, and discovery applies it relative to the subscription base.
PLAN's `[roots.sovran] exclude = ["agents/state", …]` says "never synced". For
a host subscribed to `.sovran/agents`, though, the unit-relative path is
`state`, so `agents/state` (and `**/agents/state`) do not match, and per-machine
daemon state syncs. Inside every repo unit, `src/generated` means
`<repo>/src/generated`. The notes record this under "noticed, not fixed". The
branch makes it sharper by rooting slash patterns. Inspection, not a run.
*Decide before apply:* make slash patterns root-relative (per unit, strip the
unit's root-relative prefix: `agents/state` in unit `.sovran/agents` becomes
`/state`, and is dropped where it can't apply), or refuse slash patterns in
fleet.toml unless they start with `**/`.

**P4. A symlinked subscription base is not followed, and a dangling one is not
"missing".** `src/repos.rs:74-82` uses `symlink_metadata(base)`, so a base that
is a symlink becomes a single loose *file* entry, the link itself.
*Reproduced* with `--as work2 → vol/work2`:
- Mounted, the loose unit is `Conflict: no baseline, both populated`: the leaf
  hashes a link, while home hashes a directory.
- After the volume is gone, there is no F4 error, because the link exists. The
  repo units fall to `DeletedOn` (blocking, so still safe) and the loose unit
  reads `Nothing`.

A symlink to an external volume is the most likely `--as` layout. Pre-existing.
*Fix:* follow symlinks for the base only (`fs::metadata`); dangling means
`exists: false`.

**P5. While fleet.toml is broken, `Heartbeat` fails.** `src/daemon/home.rs:158`
reads `self.fleet()?.lease` for the lease length. The notes call this
conservative, and it is today. Once F3's v0.2 half lands (a lost lease kills the
rsync child), a typo saved during a transfer aborts every in-flight sync in the
fleet, leaving markers to resume. Leases do not need fleet policy to stay alive.
*Fix:* refresh with the lease length the entry was granted (each entry already
carries it); keep the fail-closed reload for everything that reads policy.

## The nine questions

**1. Exclude/rsync agreement.**
- **Real rsync, not a mock.** `rsync_diff_tests.rs:128,137` runs
  `Command::new("rsync")` from PATH, here `/usr/bin/rsync` (openrsync). That is
  the same lookup production uses.
- **Drift constructed, and caught.** Always escaping `\` fails the `we\\ird`
  case. Dropping the zero-directory twin fails 4 of 6 differential tests.
- **Drift found that the test misses:** P2.
- **Refusals for byte vs char semantics.** The refusals of `?`, `[!…]`/`[^…]`
  and non-ASCII inside a class are complete. Everything else (`*`, ASCII
  classes, literal UTF-8) compares the same bytes either way, and NFC/NFD names
  miss identically in both engines. The one class hole is P2, which is a
  separator problem, not a byte problem.
- **Anchored carve-outs from `push_exact`.** Every special character I tried
  agrees. The one difference is the directory-only flag on `except` files (P1).
- **Pre-existing, out of scope.** Non-UTF-8 names are skipped by the walker and
  moved by rsync.

**2. Parallel walk.**
- **Deterministic.** `discover` sorts every list (`repos.rs:89-91`). Removing
  the sort fails 4 tests, and the reference test compares against the serial
  walk under three exclude lists.
- **Unchanged behaviour.**
  - Repos and worktrees are recorded and returned `Skip`, so they are not
    descended (`walk.rs:75-84`).
  - Excludes are applied before `git_marker`, as in the old walk.
  - Hidden and gitignored files are seen (tested, including `.ignore` and
    `.rgignore`).
  - An unreadable directory is `Error::Io` (tested).
  - `.git/objects` skipping lives in `all_names`, which is still serial and
    unchanged; `discover` never enters a repo, so it never sees `.git`.
- **Ignore sources.** Every `standard_filters` source is off individually, plus
  `require_git(false)`. No custom ignore filenames and no overrides. The
  `ignore` crate reads no environment variables, and the git config
  (`core.excludesFile`) only via `git_global`, which is off. No path
  re-enables them; N2 is future-proofing only.
- **Threads.** `state::workers()`, capped at 16. N3 notes one nested case.

**3. F4 can't be bypassed.**
- **Covered:**
  - An `--as` path that is missing or renamed is `Error::Missing` before
    `Acquire` (tested).
  - A missing home root is always an error (tested).
  - A missing home base below a root is an error when a baseline exists
    (tested).
  - First pull and first push still work (tested).
- **Mounted-over empty base** (exists, empty): every unit with a baseline
  becomes `DeletedOn`, blocking, with no `direction()` (probe, both repo and
  loose units). Units without a baseline take the first-sync rows. Those only
  ever pull into, or push onto, the empty side, never `--delete` from it.
  Baselines of sibling subscriptions don't count (`bases.rs:23`, `is_within`).
  **Safe.**
- **Not covered: a root removed or mistyped in fleet.toml.** `served()` drops
  the spec (`home_serve.rs:45-49`), and every baseline under it becomes
  `Remove` (`plan/mod.rs:214-237`), whose diff is `rsync --delete` from an
  empty source into the leaf. Probe: changing `[roots.work] path` to a
  nonexistent `work2` makes `work/r` read `Remove`. This is **F5**, still open
  and still a v0.2 entry criterion. With F11, though, the hand edit takes
  effect on the next request, with no restart needed. Land F5 before apply.
- **Not covered: symlinked bases** (P4).
- **Note.** One missing base fails the whole plan, every subscription included.
  That is conservative and per PLAN.

**4. `refs/remotes` exclusion.**
- **Kept:** `refs/heads`, `refs/tags`, `refs/stash`, notes, replace refs, and
  a local branch named `refs/heads/refs/remotes/x` (tested). The format is
  `%(refname) %(objectname)` (`git.rs:71`), so the `starts_with` filter applies
  to the name. HEAD is hashed separately.
- **Hash unchanged for repos without remote refs: verified.** I hashed the same
  on-disk repo (tag, stash, dirty, untracked) with `main` and with HEAD and got
  an identical hash. The equivalence holds because the output always ends in
  `\n`, and ref names cannot contain `\r`.

**5. F11 reload.**
- **Home's own writes cannot be seen half-done.** They are `write_atomic`
  renames made under the same mutex that reloads, and each one is a new inode,
  so the stamp moves.
- **A hand edit saved in place** (truncate, then write) can be read mid-save by
  one request. The next look sees a different length or mtime and reloads. A
  truncated file usually fails to parse, and that fails closed.
- **A missed edit** needs two same-length, same-inode edits inside one
  timestamp tick (milliseconds on APFS and ext4; 1 s on HFS+ or some NFS). Not
  a practical concern for hand edits.
- **`approve` does preview from disk.** `preview_allow` and `approve` both go
  through `fleet()` (`home.rs:206-215`), and the reload test covers a hand
  edit seen by preview and kept by the approve write.

**6. F8 probe.**
- **No realistic false "disconnected".** The client never half-closes and
  sends nothing while waiting: no `shutdown`, and no close_notify before the
  reply (`remote.rs:174-219`). The server's TLS stream has consumed the whole
  request, so the kernel buffer is empty and the peek returns `WouldBlock`.
  `MSG_PEEK` with `O_NONBLOCK` behaves the same on macOS and Linux (EAGAIN
  while idle, 0 on FIN).
- **Failure modes that remain:**
  - `set_nonblocking` failing returns `false`; harmless.
  - A peer that vanishes without a FIN reads as connected until
    `MAX_QUEUE_WAIT` (noted by the implementer).
- **Expiry at the head is consistent.** The entry is removed before
  `started_at` is set, `notify_all` wakes the next entry, the event is
  journaled as `expired`, and markers are untouched. A non-head waiter is
  expired by the reaper, and its thread exits on "removed while waiting".

**7. `write_atomic` fix.**
- **Unique across processes.** The name is `<file>.tmp.<pid>.<n>`, and pids are
  unique among live processes, so two daemons, or the CLI and the daemon, never
  share a name. A recycled pid only overwrites a stale leftover.
- **No cleanup on failure.** A failed `write` or `rename` leaves the temp
  behind. `Store::all` skips anything not named `*.json`, so it is a leak, not
  a misread (N5, pre-existing).

**8. Timing.** Reproduced: 346 → 138 ms on `/Users/morgan/work` (notes: 342 →
123), with identical repo and loose counts.

**9. Read-only.** Every new `fs::write`, `create_dir`, `remove_*`, `put` and
`Command::new` in the diff is in a test file. New production I/O is read-only:
`git::index_entries` opens `.git/index` read-only, and the walker uses
`symlink_metadata`. `rsync.rs` is unchanged, so `--dry-run` is still hardcoded
(`rsync.rs:156`) and `debug_assert`ed. The new `DeletedOn` diff is one more
dry run (`diff.rs:50-57`). No new path writes to a synced tree.

## Nits

- **N1.** `config/fleet.rs:176` tells the user to "write it unanchored (e.g.
  `agents/state`)". `agents/state` is now rooted at the unit; say "without the
  leading `/`".
- **N2.** `repos/walk.rs:113-120`: write it as
  `.standard_filters(false).require_git(false)`, so a future `ignore` default
  can't slip in. Equivalent today.
- **N3.** `units/snapshot.rs:166`: `discover` runs inside
  `parallel_map(workers())`, so a burst of "plain dir where the other side has
  a repo" units can spawn up to 16×16 threads.
- **N4.** `daemon/home_serve.rs:102` stats each root under the fleet mutex. A
  hung network mount blocks every request on home, heartbeats included. Copy
  the root paths out and stat them after releasing the guard.
- **N5.** `config/mod.rs:163-164`: remove the temp file on a failed
  write/rename (pre-existing).
- **N6.** `exclude/rsync_diff_tests.rs` is 315 lines, over the ~300 guideline.
  Split the fixture out.
- **N7.** This branch edits PLAN rev 4's `[roots.sovran]` hunk, which rev 5
  rewrites (rev 5 adds `"replicant"` and lacks the "relative to the unit"
  sentence). Carry the sentence into rev 5 when the docs merge.
- **N8.** Versioning. Patterns that loaded in 0.1 are now refused, slash
  patterns changed meaning, and old and new ends must upgrade together. This
  ships as **0.2.0**, not 0.1.x. `Cargo.toml` still says 0.1.0, which is fine
  if the bump happens at tag time.

## What's done well

- **Parse once, render twice.** The globset glob and the rsync rules come from
  the same tokens, and the refusal messages say *why* and what to write
  instead. The `**/` zero-directory twin is a real openrsync finding, measured,
  not assumed.
- **The differential test runs the real binary and checks a hand-written
  expected set as well**, so it can't pass by having both sides agree on
  something wrong.
- **F4's row is narrow.** `DeletedOn` carves out exactly "Present → Empty, the
  other side unchanged". It has no `direction()`, so apply can't carry it out by
  accident, and its dry run still runs guardrail 1 toward the side that would
  lose data.
- **F11 fails closed.** A broken edit refuses requests instead of serving the
  wider stale cap, and the stamp is taken before the read.
- **F8's tests coordinate through the probe's call instants**, not sleeps, and
  there is a real mTLS end-to-end test.
- **The `write_atomic` race was found by a test and fixed with a regression
  test.** The commit discipline is good: one concern per commit, every commit
  builds, and the notes say what was *not* verified (rsync 3, thistledown).
