clippy `-D warnings` and fmt clean, write-set gate clean). Target release

## What a unit does now

Planning (`status` has no dry runs; `sync --dry-run` and `sync` do):

1. The leaf walks its side of the unit into a `Manifest` (`native/manifest.rs`)
   with the unit's excludes (root excludes rewritten for the unit,
   carve-outs, a loose unit's repos, both sides' worktrees, both sides'
   git-ignored paths), and asks home for home's side (`HomeRequest::Manifest`,
   which needs the head of the queue, a dry run's entry included; home adds
   the leaf's extras to its own root excludes, filtered to paths inside the
   unit, so they can only leave more out).
2. `diff(source, target)` is the `ChangeList`: `replace` (paths whose kind
   changes), `mkdir` (parents first), `send` (files and links), `delete`
   (children first). `itemize` renders it as the `Itemized` every consumer
   already read: summaries, guardrails 1/5/6, the digest's delete set.

Applying (`plan/apply_unit.rs`, unchanged around the transfer):

1. Confirm-delete note; the target's marker (leaf for a pull; `BeginPush`
   on home for a push, which now only opens the push's run).
2. The unit's own dry run again, either way, ahead of its marker (above it in
   the code): it must still match the plan, or the unit stops with nothing of
   it written. On a pull the receiver then holds each path to that diff.
3. The transfer (`native/transfer_run.rs`), in this order:
   1. remove the target's `.replicant-tmp-*` left by a dead run;
   2. kind changes (a directory only once its listed contents are gone and
      it is empty; never one still holding unsynced paths), then directories,
      created owner-writable;
   3. files and links over `streams` connections, one worker each: large
      files (≥ 64 KiB) largest first, one file per worker in 1 MiB chunks;
      the rest batched (≤ 1 MiB, ≤ 2048 entries a batch);
   4. a second round of the same for each repo's refs and index (`.git/HEAD`,
      `.git/packed-refs`, `.git/index`, `.git/refs/**`), so refs never point at
      objects that did not arrive, and an index never calls a file dirty that
      has yet to arrive;
   5. only once every file arrived: deletions (children first; a directory
      that still holds an excluded or ignored path stays), then directories'
      final modes, then each directory renamed into is fsynced, and on a push
      the leaf waits for home to say so;
   6. verification: both manifests walked again; the target must equal the
      source but for directories that hold what the unit does not sync.
4. Lease check (lease only, review P2), Rehash/Agree/Settle, baselines,
   the marker cleared, the journal line, all as before.

Each file: written to `.replicant-tmp-<name>` (hashed when the name is too
long) in its own directory, given the source's mode and mtime to the
nanosecond, `fsync(2)`ed, renamed over the target. A file is sent as it is
when it is sent (fresh `lstat`, never through a link, `O_NOFOLLOW`); one
that changes while it is read is discarded, never installed.

On a push, what a deletion removes is renamed into
`backup/<host>/<push>/run-<n>/<rel>`, and what a write replaces gets a hard link
there before the rename takes its name, so the target stays there throughout (a
whole copy, by way of a temporary name, when the backup is on another filesystem).
A kind change is the exception: its old kind goes before the new one arrives. A
directory removed, made or changed in mode is noted first in `run-<n>.dirs`,
beside the run's directory. Those two are the record: `record_run` and
`rollback` read them.

## Frames

`u32` payload length (big-endian), `u8` kind, payload ≤ 8 MiB (an oversize
frame is an error, nothing written; lists are split at about 1 MiB). After the
TLS handshake the dialer writes `replicant-data\n` (a request's first byte
is `{`).

| kind | dir | payload |
|---|---|---|
| `Hello` 1 | leaf → home | JSON: version, host, lease, rel, kind, is_file, direction, ack_timeout_ms |
| `Ready` 2 / `Refused` 3 | home → leaf | empty / JSON reason |
| `Ack` 4 / `Fail` 5 | receiver → sender | empty (`Deletes`: JSON paths kept) / JSON reason; `Fail` ends the connection |
| `Clean` 10, `Replace` 11, `Mkdirs` 12, `Deletes` 18, `DirModes` 19 | leaf → home (push) | JSON |
| `Batch` 13 | sender → receiver | `u32` header length, JSON entries, the files' bytes in order |
| `FileStart` 14, `Chunk` 15, `FileEnd` 16, `FileDiscard` 17 | sender → receiver | JSON entry / raw bytes / empty / empty |
| `Get` 20 | leaf → home (pull) | JSON paths; home answers with a batch or one file's frames, then `Done` |
| `Done` 30 | either | the connection's (or a `Get`'s) end; a push's is acked, once home's names are synced |

Every frame is acked in order, up to 8 in flight per connection. The ack
timeout (60 s; `Hello` carries it, home clamps it to 100 ms-600 s) is the
socket timeout: no ack or frame within it and the connection is dead. Home
checks that the lease is still the head of its queue (a sync's entry) before
every frame of a push, and before every `Get` of a pull, not per chunk (reads
harm nothing). A `Replace` no longer carries what lies under a directory: that
goes first, as `Deletes`. No version bump: nothing older than this is deployed,
and home and leaves upgrade together.

## The write set

Held to the code by `write_set_tests.rs` (lists: `write_set_allowed.rs`,
`write_set_spawns.rs`, `write_set_native.rs`). New patterns: `set_times(`,
`libc::utimensat(`, `libc::futimens(`, `libc::utimes(`. Gone with rsync:
`child::run(`, `.run(`, `::run(` and the `child::run` import rule. Checked
after the change: a stray `std::fs::write` in `native/receive.rs` and a real
transfer (`ops.apply`) in `plan/diff.rs` each turn it red, by file and
pattern.

| what | where | written by |
|---|---|---|
| synced paths | leaf (pull, removal, delete here), home (push, delete on home) | the native receiver only (`native/receive*.rs`), through `Ops::apply` |
| what a push replaces or deletes on home | `backup/<host>/<push>/run-<n>/`, `run-<n>.dirs` | the receiver: rename or hard link (`native/backup.rs`, whole copy on `EXDEV`), and a line per directory |
| rollback's restores, deletions, kept copies | home's unit, `backup/<push>/rollback/` | `native::local` (`copy_listed`, `delete_listed`), through the receiver |
| markers, baselines, push manifests, contacts, journal | as before | as before |

## What holds after each failure

Same shape as the v0.2 table; the rows that changed are the transfer's.

| failure | synced paths | marker | baselines | journal | exit | later units |
|---|---|---|---|---|---|---|
| blocked (gate), `n` at the prompt, plan changed since confirmed | untouched | none | untouched | as before | 2 / 1 / 1 | untouched |
| a unit changed since the plan, either way (its own dry run differs) | earlier units done; this one untouched | none for it (a resume's stays) | earlier written | `failed at <unit>` | 1 | untouched |
| a pull meets a path that moved since that dry run | whole files only; that path and everything after it untouched | stays | not written | `interrupted (… changed/appeared on this side since the plan was made …)` | 1 | untouched |
| a thread of the transfer panics | as a connection dying | stays | not written | `interrupted (a transfer thread panicked …)` | 1 | untouched |
| home refuses the data connection (lease not at head, unit not served, no push begun, too many streams) | untouched (kind changes and directories of a pull may be done) | stays | not written | `interrupted (home refused the data connection: …)` | 1 | untouched |
| a connection dies or is cut mid-unit | whole files only: each is the source's or the target's old one (a kind change under way: neither yet; on home the old one is in the backup); no temporary left | stays | not written | `interrupted (the other side closed the data connection)` | 1 | untouched |
| a receiver stops answering (stall) | as above | stays | not written | `interrupted (no answer from the other side within the ack timeout; the connection is dead)` after the ack timeout | 1 | untouched |
| home's receiver fails a frame (disk full, a path it refuses) | as above | stays | not written | `interrupted (<home's reason>)` | 1 | untouched |
| lease lost while the transfer runs | as above; every connection shut at once, home refuses the next frame | stays | not written | `interrupted (lease lost; transfer stopped)` | 1 | untouched |
| the CLI hangs up mid-unit (Ctrl-C) | as above | stays | not written | `interrupted (the CLI hung up …; transfer stopped)` | — | untouched |
| a hangup once the transfer finished and verified | written | cleared | written | the unit's `… ok`; then `stopped before this unit began` | — | untouched |
| the source changes while sent (a live tree), or verification finds anything else left | written, whole files only | stays | not written | `interrupted (after the transfer N paths still differ …)` | 1 | untouched |
| the leaf daemon dies mid-unit | whole files only; a temporary can be left | stays (a file) | not written | home: `expired` when the lease runs out | — | untouched |

Every "stays" resumes on the next `sync` exactly as before (a marker
resumes only its own unit; guardrail 6 holds a resume over newer leaf work).
The resume re-diffs: what already arrived is not sent again, and the dead
run's temporaries are removed first. A push's resume is another run of the
same push, backed up into its own run directory.

## Benchmark

`daemon/daemon_bench_tests.rs`, ignored by default:
`cargo test --release --lib -- --ignored --nocapture bench_pull`. A pull of
the loose `work` through the real daemons over mTLS on loopback, Apple M4
Max, release build, APFS. The unit's own time (from its marker to its
journal line):

| tree | streams=1 | streams=4 |
|---|---|---|
| 10,000 × 1 KB files | 1.75 s, 5.7k files/s | 0.85-0.88 s, 11.4-11.7k files/s |
| one 2 GiB file | 1.24-2.69 s, 0.8-1.7 GB/s | 1.20-1.27 s, 1.7-1.8 GB/s |

A file is never split, so the 2 GiB pull uses one connection either way;
the spread is between runs (the slow one was the first large write of a
run), not streams. ~1.7 GB/s is ~14 Gbit/s on one stream, bound by TLS and
the copy on loopback; a real 10 Gbit link should be the limit. Not measured
on the owner's LAN or over Tailscale.

The first run of the small-file case took 49 s (200 files/s): Rust's
`File::sync_all` is `F_FULLFSYNC` on macOS, a drive-cache flush per file.
The receiver now calls `fsync(2)` (`native::fsync`), which is what
`sync_all` is on Linux; rsync never fsynced at all.

## Deleted, and why

- `src/rsync.rs`, `src/rsync/*` (runner, child process control and process
  groups, client detection and remote-path quoting for openrsync, itemized
  output parsing for both rsync flavours, spill files for long exclude
  lists, scratch dirs, the empty-source and skeleton tricks for list
  deletes, ssh options) and their tests: the transfer is native.
- The rsync half of the exclude engine (`rsync_rules`, `rsync_args`,
  `literal_rule`, the differential tests against the system rsync and their
  fixture): one globset matcher now serves every walker on both sides.
- `rsync_timeout_secs` and `rsync_host` in leaf.toml (still read so an
  older file loads; ignored; never written), `subscribe --rsync-host`,
  `Error::Rsync`, `plan::RSYNC`, the scratch dir, `BeginPush`'s backup list
  and home's copy before a push (the receiver renames).
- Tests that only existed for rsync: 64 (629 → 565).

Kept, deliberately: `repos::ignored`'s lists of git-ignored paths. The brief
listed "gitignore materialization" for deletion; the lists are what let a
transfer leave a path ignored on *either* side alone on *both* (each side's
list crosses the wire and the transfer excludes their union), which
`plan/tests_ignored.rs` pins ("a path ignored on one side only is left
alone", a push neither sends the leaf's ignored files nor deletes home's).
Applying each side's own rules at walk time would send or delete a path
ignored on one side only. What is gone is their rsync rendering.

## Decided here (flag for review)

- **Backup layout** stays `backup/<host>/<time>/run-<n>/<rel>` (the brief
  said `<push-id>/<rel>`): a resumed push is a second run whose originals
  must not overwrite the first run's, and rollback reads runs.
- **A mode-only change** is shown `a` (not touched: guardrails 1 and 6 skip
  it) but the file is resent whole, per "send when mode differs".
- **A symlink's mode** is never compared or set (not portable; Linux
  cannot set it). A **directory's mtime** is not kept (not state).
- **Verification after every transfer** (a fresh diff both ways) fails the
  unit `Interrupted` if anything but kept directories is left. On a live tree
  that can recur, as rsync's exit 24 did (N4).
- **`.git` without `HEAD` is not a repo** (`repos::git_marker`), and a
  repo's refs and index go in a last round. Found by the native fault tests: an
  interrupted pull of a new repo left a `.git` without `HEAD`, discovery
  called it a repo, `git status` failed, and every later plan failed, the
  resume included. rsync could leave the same state.
- **`fsync(2)`, not `F_FULLFSYNC`**, per file (see Benchmark). Durable to
  the device; not a drive-cache barrier on macOS.
- **Home's policy on data connections:** home refuses to send or write a
  path its own root excludes or carve-outs exclude, whatever the leaf asks.
- **Streams** are enforced on home per (lease, unit): one more than
  `[daemon] streams` is refused.
- **`.replicant-tmp-*` is a built-in exclude**, so a dead run's temporary is
  never state, never sent, and is removed by the next transfer of its unit.
- **Wire 5** (home and leaves upgrade together; `BeginPush` lost its
  `backup` field), **local wire 6** (`UnitProgress`). `subscribe
  --rsync-host` is gone (a CLI break, 0.x).
- **Pattern grammar unchanged.** It was the subset rsync could read the same
  way; widening it (`?`, `{a,b}`, negated classes) is possible now and not
  done. Refusal messages no longer cite rsync.
- **Progress** is drawn at a terminal only (`\r` redraw of the unit's line);
  without one it is left out of the stream, and `--json` keeps every event.

## Open items

- Not run on Linux, nor between two machines, nor over Tailscale or the
  10 Gbit LAN. The first real push should be watched (journal, `status`),
  as before.
- One large file uses one stream (decision 3); ~1.7 GB/s on loopback.
- A run whose leaf dies before it reports: rollback restores everything the
  run's directory and notes hold, and removes the directories it made. Files it
  created stay ("a run never reported on may have added files that stay"), and
  if it turned a file into a directory, whose files nobody listed, the rollback
  fails loudly with the original safe in `backup/`.
- **Not from the review, not fixed here: a macOS kernel race.** A read on an
  `AF_UNIX` socket that has `SO_RCVTIMEO` set can block forever if another thread
  calls `shutdown` on it as the read times out and re-enters: the timeout never
  fires. It is not this work's: the review's own commit, unchanged, hung this way
  in `watch_hangup` on its second full-suite run of 13. Two places rely on that shutdown:
  `daemon/local.rs`'s `watched`, in production (the handler has finished and the
  CLI never gets its answer), and `Faulty`'s socket pairs, in tests. Reproduced
  without replicant: a 60-line probe hung 62 times in 1.2M iterations (`SHUT_RD`),
  44 in 521k (`SHUT_RDWR`), and 0 in 16k over TCP, which is too few to clear TCP:
  the data plane's production sockets. During this work the full suite hung
  this way twice in some 25 runs, once in `daemon::local::tests::serve_streams_...`
  and once in `Faulty`'s `serve_data`; each was sampled, killed and re-run. So
  a full `cargo test` can hang on macOS, today, until this is fixed: run it under
  a bound.
  A watch built on `poll(2)` with its own timeout would not depend on either.
- A home data connection blocked writing to a leaf that vanished holds its
  thread (and its stream slot for that lease and unit) until the ack
  timeout.
- Home's manifest of a unit is one JSON reply on the control link (short
  keys); `MAX_MESSAGE` (64 MiB) bounds it at roughly half a million entries.
- Verification re-walks both sides of every unit after its transfer, so a
  unit's dry-run cost is paid twice per apply (expected, not measured on the
  owner's 70k-entry loose `work`).
- Files over ~300 lines that were already over: `plan/tests.rs` (322),
  `daemon/daemon_identity_tests.rs` (314), `config/fleet.rs` (311, +6
  here), `cli/render_tests.rs` (305); `daemon/home.rs` is 303.
