# replicant v0.1 — review

Reviewed 2026-10-31. Snapshot of branch `bsneed/v0.1` at
`21c1cd6badc4697f4bb14236359109b8e06d4c2c`, base `main` =
`ebacadd5af6919de18a292d44f9aded00dc905ad` (range `ebacadd..21c1cd6`, 18
commits). Clean tree: no staged, unstaged or untracked inputs. Measured against
`docs/PLAN.md` (rev 4) and the brief for this review. I read
`docs/v0.1-notes.md` before the code, so this is not a blind assessment of the
notes' claims.

## Verdict: merge with fixes

v0.1 meets its read-only contract, and the evidence is the code, not the
comments. The only production `Command::new` calls are `git` (with optional
locks off) and `rsync`, and `rsync` always gets a hardcoded `--dry-run`. No
synced path, baseline or marker is ever written. The tests take before/after
fingerprints of both trees (bytes, mode, mtime, `.git/index` included) and
pass. The code is well built: small modules, real fixture repos, versioned
records, edits to fleet.toml that keep comments.

Fix **F1–F3** before merge, or at least before the first dry run over ssh.
They are cheap, and they break the one thing v0.1 exists to do: dry-run the
real tree from a Mac against thistledown. **F4–F7** are latent in v0.1, because
nothing applies yet. They should be the entry criteria for v0.2.

## Findings

### Major

**F1. A hung ssh wedges home's queue for the whole fleet.** `src/rsync.rs:151`
runs rsync with no timeout. ssh gets no `BatchMode` and no
`ConnectTimeout`/`ServerAliveInterval`. Meanwhile the heartbeat thread
(`src/plan/diff.rs:30`) keeps the lease alive for as long as `f()` blocks. A
Tailscale SSH check-mode prompt, a host-key prompt on the daemon's controlling
tty, or a partition mid-transfer holds the head of home's queue until someone
kills the leaf daemon. Every other leaf's dry run waits, then gives up after
`MAX_QUEUE_WAIT`.
*Fix:* `-e "ssh -o BatchMode=yes -o ConnectTimeout=10 -o ServerAliveInterval=15 -o ServerAliveCountMax=2"`,
plus a wall-clock bound on the child (kill and error).

**F2. Over ssh from a Mac, home's path goes through home's shell unquoted.**
`src/rsync.rs:106` builds `host:/path/`. The probe shows openrsync hands it to
ssh as a single word (`[/home/morgan/work/it's a repo/]`). ssh joins its argv,
and the remote shell parses the result. A unit path containing a space,
apostrophe or parentheses therefore fails the remote shell, and because of the
`?` at `diff.rs:126` that fails the **entire** dry run. A path containing
`$(...)` runs as a command on home. The notes (`v0.1-notes.md:133`) say
"rsync ≥ 3.2.4 on home protects arguments". That is wrong: 3.2.4's escaping
happens in the *client*, and a Mac's client is openrsync. Linux leaves running
rsync ≥ 3.2.4 are fine.
*Fix:* detect openrsync once (`rsync --version`) and single-quote the remote
path for that client only, since rsync 3.2.4+ would otherwise escape it twice.
Add a test using a fake `-e` script that asserts the argv.

**F3. Losing the lease is silent.** The heartbeat loop `break`s on its first
error (`src/plan/diff.rs:33`), and `Release` errors are discarded
(`src/plan/mod.rs:116`). One transient dial failure, or a restart of home's
daemon (the queue lives in memory), ends the heartbeats. The lease then
expires, the next entry proceeds while this leaf's work is still running, and
the plan still reports success. This is the brief's question 5: **yes**, an
expired entry's rsync can still be running when the next entry proceeds. In
v0.1 that is two dry runs overlapping. In v0.2 it is two real rsyncs
interleaving on home.
*Fix now:* retry heartbeats within the lease window; on a definitive "not in
the queue", set a flag the plan checks, and fail the plan with "lease lost".
Make a failed `Release` an error.
*v0.2:* the flag must also kill the rsync child.

**F4. A unit that vanishes reads as an ordinary change, and the table sends a
whole-unit delete.** `repos::discover` turns `NotFound` into empty
(`src/repos.rs:62`), and `decide` treats a move to `Empty` like any other
change (`src/decide.rs:134`).
- Leaf side: rename `~/work2`, or point `--as` at an unmounted volume. Every
  unit becomes "leaf changed", so **push** runs with `source_absent`
  (`diff.rs:124`): `rsync --delete` from an empty directory into home, the
  backup.
- Home side: an unmounted or renamed root does the same in the pull direction
  to every leaf.

Guardrail 1 only protects dirty repo files.
*Fix:* a subscription base that is missing on its own side is an error, not
`Empty`. A unit going Present→Empty since baseline is its own row: "deleted on
X", which requires explicit confirmation. Add both to the table and to tests.

**F5. The `Remove` row is unconditional, and too many things trigger it.**
`src/plan/mod.rs:188` emits `Remove` for any baseline outside the *served*
specs. That includes paths home refuses because a cap was narrowed or a root
was removed or mistyped (`home_serve.rs:45-50`), not only explicit
`unsubscribe`. It also ignores whether the leaf changed since the baseline, and
it ignores markers. In v0.2 this deletes unpushed leaf work in loose units,
which guardrail 1 does not see. Guardrail 5 says paths outside bounds are
"never deleted, in either direction".
*Fix:* `Remove` only for paths the host explicitly unsubscribed (home can
report them), and only when `leaf == baseline.leaf`; otherwise conflict.

**F6. Gitignored files can be destroyed silently, which is worse than the notes
say.** Proposed change 1 says they "never trigger a direction". That is true,
but the real hazard is the other side of it. The hash ignores them
(`git.rs:71`, no `--ignored`), and so does guardrail 1 (`guard.rs:73`, porcelain
paths only). So any pull or push triggered by *another* change overwrites or
`--delete`s the target's ignored-but-not-excluded files with no refusal. A
leaf-only `.env.local` disappears on the next pull. See Q9.1 for the fix.

**F7. Guardrail 4 misses collisions between units.** Collisions are computed per
unit (`src/units.rs:230`). The loose unit excludes every repo
(`units.rs:137-141`), and each repo unit walks only itself. So two repos
`work/Foo` and `work/foo`, or a repo and a loose sibling that differ by case,
are never compared, and both land in one directory on APFS. Also unchecked:
NFC/NFD pairs, which APFS treats as the same name.
*Fix:* home runs one extra collision pass over the union of unit roots, plus
names normalized with `to_lowercase` and NFC (NFC needs
`unicode-normalization`, or document it as out of scope).

### Minor

**F8. Lease liveness doesn't actually check the waiter's connection.**
`queue.rs:11-13` says "a connected waiter is by definition not dead", but
`queue.rs:148` refreshes the lease without checking the socket. A leaf that
dies while waiting keeps its entry alive for up to 10 minutes. When it reaches
the head it gets a lease nobody heartbeats, so it holds the queue for one more
lease period.

**F9. Push deletions from openrsync to rsync 3 may come back without names.**
openrsync forwards only `--log-format=%i` (no `%n`) to the server (probe:
`[--log-format=%i]`). On a push, deletions happen on home's rsync 3. If those
lines come back as a bare `*deleting`, then `parse` (`rsync.rs:180`) records
deletions with an empty path, and guardrail 1 can't match them against home's
dirty files. Not reproduced (no rsync 3 here); test Mac→Linux push with a
deletion before v0.2.

**F10. Non-ASCII names can defeat guardrail 1's textual match.** rsync 3
escapes high-bit bytes as `\#ooo` unless the locale says they are printable,
and a daemon under systemd or launchd often has no `LANG`. git reports raw
UTF-8. `guard.rs:84` compares the two strings, so a dirty `café.txt` isn't
matched. *Fix:* pass `-8`. openrsync accepts it (checked: exit 0, prints raw
UTF-8 either way). Test with one non-ASCII file.

**F11. Hand edits to fleet.toml are ignored until the daemon's next write.**
`Home` caches the parsed `Fleet` (`daemon/home.rs:42-49`) and reloads only
after its own writes. If Brandon narrows a cap by hand, it is not enforced
until a restart or until any host subscribes. Reload when the file's mtime
changes, or say "restart the daemon" in fleet.toml's header comment.

**F12. The trust model exposes more than assumption 11 admits** (see Q1).
Impersonation reaches *other hosts'* subscriptions (`Unsubscribe` as
birchbook), markers (resuming another leaf's push) and queue entries. Two
machines that share a short hostname collide by accident, with no hostility
needed.

**F13. `approve` is three separate atomic writes** (`subscribe.rs:258-274`). A
crash between `set_host` and `remove_pending` leaves the host both enrolled and
pending. Do it as one `toml_edit` document write.

**F14. The empty-source stand-in is a predictable temp path**
(`rsync.rs:144`): `temp_dir()/replicant-empty-<pid>-<n>`, created with
`create_dir_all`. On a Linux leaf's shared `/tmp`, whatever pre-exists there
(a directory, or a symlink to one) becomes the rsync *source* for a deletion.
In v0.2 that is the source of a `--delete` push. Use a `mkdtemp`-style
directory under the config dir.

## The nine questions

**1. Trust model.** Beyond the notes, any holder of the bundle can:
- rewrite another host's subscriptions (`Unsubscribe` as that host). In v0.2,
  that host's next sync turns it into `Remove`;
- resume or own another host's home marker (`decide.rs:101` compares a
  self-asserted name);
- read the whole fleet (`FleetState`);
- create pending entries under any name;
- hold the queue.

The bundle also carries home's *server* key (`certs.rs:62-71`: one identity for
both ends), so a leaf can impersonate home. Accidental collisions are the real
risk, not hostile ones: two boxes with the same short hostname share an
identity completely.

The cheap fix for v0.2, before apply, needs no new dependencies:
- `config export-creds <host>` mints a per-host client cert from the existing
  CA. rcgen is already a dependency.
- `fleet.toml` records `[hosts.x] cert = "sha256:<DER fingerprint>"`. sha2 is
  already a dependency.
- After the handshake, home hashes `conn.peer_certificates()[0]` and derives
  the host from the fingerprint. It ignores `call.host`, or refuses on a
  mismatch.
- Home's server cert becomes separate from client certs.

Fingerprint pinning avoids needing an X.509 parser to read a SAN. Enrollment
already requires copying a bundle by hand, so make that bundle per-host.

**2. Read-only proof.**

| site | what | class |
|---|---|---|
| `git.rs:41` `Command::new("git")` | `for-each-ref`, `status --porcelain=v2`, with `--no-optional-locks` + `GIT_OPTIONAL_LOCKS=0` | read-only; tested against `cp -Rp` stale-stat repos with `.git/index` bytes+mtime unchanged |
| `rsync.rs:151` `Command::new("rsync")` | args from `Transfer::args`, which hardcodes `--dry-run` (`rsync.rs:115`) + `debug_assert` | dry run only; no other rsync call site exists |
| `config/mod.rs:144` `write_atomic` | fleet.toml, leaf.toml, `state/` records (contacts only in prod) | config dir |
| `daemon/certs.rs:96` | `ca.key`, `ca.pem`, `credentials.pem` | config dir |
| `daemon/journal.rs:126` | `journal.log` append | journal |
| `daemon/mod.rs:58-112` | config dir perms, `daemon.lock`, `replicant.sock` | config dir |
| `rsync.rs:147/156` | empty stand-in dir in `temp_dir()` | temp (see F14) |

No write targets a synced path. Baseline/marker `put` is reached only from tests.
`sync` without `--dry-run` is refused in the CLI (`cli/mod.rs:131`, tested). The
config dir is `$HOME/.config/replicant`, outside every root in PLAN's example.
Nothing stops someone configuring a `.config` root, though. Hardening: add
`-c core.fsmonitor=false` to the git calls. A repo with fsmonitor enabled makes
`git status` start a daemon that writes into `.git/`. It is not enabled
globally here.

**3. State hash.**
- **Sound for what it covers.** It is built only from content and object ids:
  HEAD text, `for-each-ref` names+oids, porcelain v2 (modes, blob ids, XY), and
  bytes of files that differ from the index. Nothing comes from `stat`, so the
  same repo hashes the same on two machines.
- **Loose units** use (path, kind, size, mtime seconds, mode, link). That is
  stable wherever rsync or Syncthing carried the files. Comparing each side
  only against its own baseline (assumption 5) makes this safe.
- **Blind to things rsync moves:** ignored files (F6), `.git/config`, hooks,
  `info/exclude`, reflogs (including stash entries below the top one, a stated
  requirement), and `skip-worktree`/`assume-unchanged` flags.
- **Over-sensitive:** IDE autofetch changes `refs/remotes/*` on both machines,
  which turns every such repo into a conflict. Consider dropping
  `refs/remotes/` from the hash. They are refetchable, and rsync moves them
  anyway.

**4. Decision table.** Each row matches PLAN plus the notes' extras, and
`decide_tests.rs` covers each one. Wrong-direction cases: F4
(Present→Empty reads as a normal change, which sends a whole-unit delete) and
F5 (`Remove` outside the table, unconditional). Marker rows follow PLAN, so
resuming overwrites post-interruption edits in loose units with nothing to stop
it. Keep guardrail 1 active on resume in v0.2 (today it is). The quarantine
check trusts self-asserted names (Q1).

**5. Queue + leases.**
- Expiry versus a live heartbeat is race-free inside the mutex.
- A running expired entry: yes, see F3.
- Dead waiters: F8.
- Holds can't be created in v0.1 (`EntryKind::Hold` appears only in tests), so
  none can be orphaned today. For v0.4, a hold outlives the CLI process, so
  something must heartbeat it. If home's replicant daemon does, a killed agent
  orphans the hold forever. Tie the hold's liveness to the agents daemon's view
  of the agent (pid or agent status), not to replicant.

**6. openrsync vs rsync 3.** The parser accepts both widths (`>= 9`) and infers
openrsync's slashless deleted directories. Both fixtures pass. The rsync 3
fixture contains `link -> target`, which `%n` never prints (`%L` does). That is
harmless but asserts something rsync does not do (`rsync_tests.rs:20,57`).

Things that will break on the first Mac→Linux ssh run:
- F2 (quoting);
- F1 (no BatchMode or timeouts);
- F9 (push deletion names);
- F10 (escaping, mainly on Linux clients).

openrsync turns `--delete` into `--delete-before` (probe), which is fine.

**7. Guardrail 4.**
- A Linux leaf is exempt, correctly: `cfg!` is false, so `case_check` is false
  and the guard skips (`guard.rs:111`).
- A Linux home serving a Mac leaf is covered: the leaf sends `case_check: true`
  and home computes the collisions.
- Gaps: F7 (collisions between units, and NFC/NFD).
- A case-sensitive APFS leaf gets false refusals. That is the safe direction,
  so acceptable.

**8. Mid-branch builds.** Confirmed: `c63d4dc` and `96e28aa` fail with E0583
(and `c63d4dc` also with E0432); `9700beb` builds again. It matters only for
`git bisect`, which can `skip` them. Not worth a history rewrite. Note it in
the merge commit message.

**9. Proposed PLAN.md changes.**
1. *Ignored files in the repo hash:* **agree, and widen it.** Add a metadata
   manifest of `git ls-files --others --ignored --exclude-standard`, filtered by
   root excludes. Guardrail 1 must also treat ignored-but-not-excluded files on
   the target as at-risk (F6).
2. *`bin` out of the default exclude:* **agree.** This only edits PLAN's example
   config; the code has no built-in `bin`.
3. *Tabulate the extra rows:* **agree.** Also add F4's "unit vanished" row and
   F5's conditions on `Remove`.
4. *Trust note in "Control plane":* **agree.** Write it as a temporary
   condition, with per-host certs scheduled for v0.2 (Q1), not as accepted
   design.

## Nits

- `state.rs:46` `short()` slices a string the peer supplied at byte 12. A
  non-ASCII value from the wire panics. Use `get(..12)`.
- `git.rs:82` decodes porcelain lossily. A non-UTF-8 path (possible on Linux)
  hashes as `<absent>` instead of its bytes, and guardrail 1 can't match it.
  Prefer `OsStr` bytes, or refuse loudly.
- `plan/mod.rs:137` fails the whole plan if the final `Report` call fails,
  after the work succeeded. Downgrade that to a warning.
- One thread per mTLS connection, with no cap and no read timeout after the
  handshake. Fine inside the trust domain; note it for when per-host certs land.

## What's done well

- Read-only is enforced by construction: `--dry-run` is not a parameter, and the
  git locks are disabled in the environment as well as by flag. The test for it
  uses `cp -Rp` stale-stat repos, which is exactly the case where git would
  otherwise rewrite `.git/index`.
- Home enforces guardrail 5 on its own side and ignores repo paths from the
  leaf that fall outside the host's bounds (`home_serve.rs:100-110`).
- The mTLS copy is faithful, with small improvements. It names the ring
  provider explicitly, uses no `danger` or unauthenticated verifiers, trusts
  only home's CA (no webpki roots), checks a fixed `SERVER_NAME` like agents,
  redacts the key in `Debug`, and refuses `0.0.0.0` listeners.
- Records are versioned and refuse unknown versions. A corrupt record is an
  error, never read as absent. fleet.toml edits keep comments.
- Each side compares hashes only against its own baseline. That makes the table
  robust to hash differences between machines without depending on them.
