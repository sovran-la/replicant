## Not done here (v0.2 entry criteria, by decision)

F4, F5, F6, F7, F8, F9, F11, F12 and the per-host-cert trust model are
deferred. They will be designed before they are built. The nit about one
thread per mTLS connection is deferred with the per-host certs. The F3 v0.2
half is also open: a lost lease must kill the running rsync child. Today
the flag is checked only before rsync starts and at the end.

## Observed while fixing (not fixed)

- `approve` previews from the daemon's cached `Fleet` but writes the file
  fresh. After a hand edit that removes the pending entry, it would still
  enroll the host. This is the same root cause as F11.
- rsync now runs in its own process group, so a terminal Ctrl-C sent to a
  foreground daemon no longer reaches rsync and ssh. Neither did the death
  of the daemon before this change. The bound still applies.
- `for-each-ref` output is still decoded lossily. Two non-UTF-8 ref names
  could hash the same. This is rare, and it is not a guardrail input.
- `docs/v0.1-notes.md` still says "rsync ≥ 3.2.4 on home protects
  arguments". That is wrong, as F2 shows. The notes were left as written.
