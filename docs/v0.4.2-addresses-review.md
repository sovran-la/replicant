# Review: replicant v0.4.1 and v0.4.2 (addresses, sticky dialer, listeners, install script)

## Summary

The dial ordering, address lists, sticky dialer and multi-listener home are sound, and no data-safety or trust defect turned up.

**Verdict: fix first.** 0.4.2 is already tagged and nothing here calls for a revert. Ship a small 0.4.3 with:

- **A1:** a silent listed address costs the full request deadline, up to 900 s, before fallback.
- **A2:** four plausible wrong implementations of the fallback pass the whole suite, including one where data connections never fall back at all.
- **A3:** the install script reports success and restarts the old binary when `cp` fails.

## Findings

### Major

#### A1. A silent listed address blocks fallback for the whole request deadline

**Where:** `src/daemon/remote.rs:338-345`, `src/daemon/leaf_link.rs:23`

**Violates:** PLAN rev 15, "if that one fails it walks the list again". The list exists so a bad route costs little.

**What happens:** `connect` uses the caller's `deadline` as the socket timeout during the TLS handshake. For every control call except heartbeat and release, that is `REQUEST_DEADLINE` = 900 s. An entry that completes TCP and never answers TLS stalls the walk for 15 minutes per such entry.

**Trigger:**
- The network dropping between SYN-ACK and the ServerHello, for example a laptop leaving Wi-Fi.
- A path that passes small packets but not the handshake flight.
- A DHCP-reused address running something silent on 7750.

These are uncommon, but the failure is a sync that looks hung. The heartbeat's 10 s path can fail over meanwhile, and the stuck call does not benefit.

**Evidence:** reproduced at reduced scale. With a silent first entry and a 1 s deadline, the live second entry connected after 1.007 s. Two silent entries at 3 s failed after 6.005 s. The 900 s figure comes from reading the code, not from waiting it out.

**Context:** the timeout itself predates this range, but it only became a fallback problem now that a list exists.

**Fix:** bound the handshake as home does (`HANDSHAKE_TIMEOUT`, 10 s), then apply the deadline:

```rust
let hs = deadline.min(HANDSHAKE_TIMEOUT);
tcp.set_read_timeout(Some(hs))?;
tcp.set_write_timeout(Some(hs))?;
// ... complete_io ...
stream.sock.set_read_timeout(Some(deadline))?;
stream.sock.set_write_timeout(Some(deadline))?;
```

Add a test with a silent first entry and a large deadline that asserts the elapsed time.

#### A2. The fallback's main promises are not held by any test

**Where:** `src/daemon/remote_tests.rs:225-296`, `src/daemon/daemon_tests.rs:286`

**Violates:** the project's exhaustive-test requirement, and the change's stated reason. PLAN rev 15's motivation is the *data* path.

**What happens:** M1 to M4 all survive 712 tests. Each breaks real behaviour:
- **M1:** a dead preferred address is retried first for the rest of the session, paying its timeout on every connection. That is the same symptom 0.4.1 fixed.
- **M2 and M3:** data connections never fall back, so a sync dies at its first unit while control calls succeed.
- **M4:** a wrong certificate on the first entry blocks a working second entry.

No test calls `open_data_any` or `HomeLink::open_data` with more than one address. Today's code is correct on the M1, M2 and M4 inputs, per the probes, but nothing keeps it that way.

**Fix:** add these tests:
1. Preferred dies, other alive: the call succeeds and `preferred()` moves.
2. `open_data_any([dead, live])`.
3. `[wrong-CA, live]`.
4. An end-to-end sync on a leaf with `[dead, live]`, which kills M3.
5. Optionally, the 16-thread loopback stress above.

### Minor

#### A3. The install script reports success when nothing was installed

**Where:** `scripts/install-macos.sh:22`

**Violates:** the script's purpose, and `set -e` does not do what the line assumes. POSIX `errexit` ignores a failure in any `&&` list member except the last, so a failed `cp` does not stop the script.

**Evidence:** reproduced with a read-only destination directory and stubbed tools:

```
cp: H/dest/replicant.new: Permission denied
replicant OLD
daemon restarted
exit=0
```

The old binary stays in place and the daemon is kicked and restarted on it. A partial `$DEST.new` from a full disk would also be left behind, though I did not run that case.

**Question from the request: half-installed binary?** No. The rename is atomic, so `$DEST` is always a whole file, and a failed sign or build stops before install (scenario F, exit 1).

**Fix:**

```sh
cp target/release/replicant "$DEST.new"
"$DEST.new" --version
mv -f "$DEST.new" "$DEST"
```

Running `--version` before the rename also means a binary that cannot start is never installed. Today it is installed first, then `--version` aborts before the restart, leaving a new CLI beside the old daemon.

#### A4. A refusal from a listed address vanishes when a later one answers

**Where:** `src/daemon/remote.rs:258-268`

**Trigger:**
- The LAN entry presents a wrong certificate: a reused DHCP address, a spoofed `.local`, a home with a rotated CA.
- The LAN name stops resolving.

**Impact:** either way, the leaf syncs over Tailscale at about 52 MB/s instead of about 190 MB/s (PLAN's figures), plus one dead-entry timeout per CLI request. Nothing says so. `failures` is dropped on success, and `preferred()` has no production reader. A handshake refused by something listening at a listed address is precisely what someone would want to hear about.

**Evidence:** inspection, plus the `[wrong-CA, live]` probe showing silent success.

**Fix:** on success after at least one failure, `eprintln!` the failures. The daemon already logs that way, for example at `leaf_link.rs:55`. Consider a journal line too.

#### A5. Multi-address errors repeat themselves and call a certificate refusal "unreachable"

**Where:** `src/daemon/remote.rs:267`, `:276-279`

**Evidence:** captured output for two dead addresses:

```
remote: home is unreachable at every address; 127.0.0.1:60647: remote: home at 127.0.0.1:60647 is unreachable: Connection refused (os error 61); 127.0.0.1:60648: remote: home at 127.0.0.1:60648 is unreachable: Connection refused (os error 61)
```

With two wrong certificates it reads `remote: home is unreachable at every address; A: tls: home at A refused the handshake with … Is that home's current bundle?; B: tls: …`.

`src/error.rs:22` assigns handshake failures to `Error::Tls`, but the list shape turns them into `Remote`. No production code matches on either variant (searched), so the impact is only the misleading wording: home was reached, and it was the certificate that failed.

**Single-address and other shapes are fine:**

```
remote: home at X is unreachable: Connection refused (os error 61)
remote: home at X is unreachable: does not resolve (…)
remote: home at [fe80::1]:7750 is unreachable: resolves only to link-local IPv6 addresses without a scope
tls: home at X refused the handshake with <path> (invalid peer certificate: BadSignature). Is that home's current bundle?
remote: home has no address to dial
```

**Fix:** have `connect` return the failure detail without the variant prefix or repeated address, and print one attempt per line. Say "home did not answer at any address" as the header. If every attempt was a TLS refusal, return `Error::Tls`.

#### A6. `subscribe --address` silently replaces a list with one address

**Where:** `src/daemon/leaf.rs:191-193`, `src/cli/args.rs:33-35`

**Trigger:** a leaf with `["thistledown.local:7750", "100.64.10.99:7750"]` runs `replicant subscribe thistledown --address thistledown.local <path>` from old notes or shell history. The list is saved as one address with no message, and the tailnet fallback is gone until someone notices away from home.

**Evidence:** inspection. Without `--address` the list is kept.

**Fix:** make `--address` repeatable and build through `Addresses::new`, or warn when it shrinks a list. `Addresses::new` also picks up trimming and dedupe, which `Addresses::one` skips here.

#### A7. Stickiness is per list entry, so a name's dead IP is paid on every connection

**Where:** `src/daemon/remote.rs:316-336`

**Violates:** the `Dialer` doc comment, "a sync's many connections pay for the dead candidates once".

**Trigger:** `thistledown.local` resolves to two IPv4 addresses, or IPv4 plus global IPv6, and the first one tried black-holes SYNs. Each connection re-resolves, waits 5 s on the dead IP, then succeeds, and the entry is recorded as preferred. That is the 0.4.0 symptom through a different door.

**Evidence:** inspection only, since it needs a real multi-address name. I did not establish how often avahi or mDNS returns such a set here.

**Fix:** the smallest correct change is to remember the resolved `SocketAddr` alongside the entry and try it first. If the shape is judged too rare, correct the doc comment instead.

#### A8. PLAN understates what a DHCP change does to home

**Where:** `docs/PLAN.md:430`, `src/daemon/mod.rs:103-106`

**What's wrong:** PLAN says "a lease change means a restart". Combined with all-or-none binding, a restart after a lease change does not recover: the old address no longer binds, and home refuses to start on *any* interface, tailnet included, until `fleet.toml` is hand-edited. Thistledown's LAN address is dynamic DHCP, so this is reachable on the deployed fleet by a lease change plus a reboot.

**Evidence:** `bind` on an address this machine does not hold fails with `could not bind 192.0.2.1:7750: Can't assign requested address`. Combined with the all-or-none `?` and M6's test, the start fails. The full start was tested with an occupied port, not a missing address.

**Context:** all-or-none is an explicit, accepted decision and is not the defect here.

**Fix:** correct the sentence to say the address needs editing, and consider a DHCP reservation for thistledown.

### Nit

- **A9. `src/config/addresses.rs:81-86`, `:157-163`.** `address = 7` and `address = ["a", 7]` print `data did not match any variant of untagged enum OneOrMany`, naming an internal type, and the test pins that text. The rest of the message (path, line, caret) is good. A small visitor can say "expected an address or a list of addresses".
- **A10. `src/config/mod.rs:166-176`.** Pre-existing, now reachable through `Addresses`, whose doc says the default port is applied. Bare `2001:db8::1` stays portless because `1` parses as a port. It fails safely at resolve time. Scoped `fe80::1%en0` gets its port and resolves correctly (tested).
- **A11. `src/config/addresses.rs:51-58`, `:67-78`.** Unused in production: both `From` impls, which also bypass the port and trimming that `new` applies; `first()` and `is_empty()`, used only by tests.
- **A12. `src/daemon/remote.rs`.** Grew from 246 to 358 lines, past the ~300-line rule, with `impl Dialer` split in two around free functions. Moving `Dialer` and `dial_order` to `remote_dial.rs` fixes both.
- **A13. `src/daemon/remote.rs:228` vs `:261`, `:270`.** `preferred()` recovers from a poisoned lock, while `connect_any` silently skips the update. Use one form; `lease.rs` uses `unwrap_or_else(|e| e.into_inner())`.
- **A14. `docs/PLAN.md:401`, `src/config/addresses.rs:6-7`.** "Pins the peer's certificate" is true of home checking a leaf by fingerprint. A leaf checks home by CA chain, name and server-only use (`tls_verify.rs:49-62`), which is not a pin. The conclusion stands, but the words should match.
- **A15. `src/daemon/daemon_tests.rs:286`.** A missing wake shows up as a test that hangs forever (M5), not a failure. Join with a bound. The test also needs `[::1]`, so it would fail on a host with IPv6 disabled (inspection).
- **A16. `scripts/install-macos.sh:26-29`.** `DEST=elsewhere` still restarts the `la.sovran.replicant` label, whose plist runs `~/.cargo/bin/replicant` on this machine, so the restart picks up a binary this run did not install. With no plist the script exits 0 silently, leaving any running daemon on the old binary. "daemon restarted" only means launchctl returned 0. Skip the restart when `DEST` is overridden, and print a line when there is no plist.

## Answers to the Specific Questions

### Concurrency

Sane, and it does not thrash in any way that costs more than a bounded number of walks.

- No lock is held across I/O: `order` snapshots, and the write happens after the dial.
- Two races exist:
  - A dial that began before an outage can overwrite the newer choice with the dead address.
  - An all-fail can clear a choice made a moment earlier (reproduced).
- Each costs at most one extra walk per in-flight dial and then heals. Clearing only if the value still equals the snapshot would remove the second race, but neither breaks a contract, so neither is a finding.
- The premise is milder than described. `transfer_run.rs:57` opens a unit's connections **sequentially**, and I found no unit-level parallelism in `plan/`. Real concurrency is the plan thread plus the heartbeat thread.

### Heartbeat budget

Default lease 30 s, heartbeat every 10 s. With two entries, a dead or silent first entry costs 5-10 s and the second still answers inside the window, so no finding. The bound does grow with list length and resolved addresses, and `getaddrinfo` is not bounded by anything here, so very long lists could exceed a lease.

### Session length

`Leaf::remote` builds a fresh `Dialer` per `LocalRequest` (`leaf_link.rs:141`). So "session" means one CLI request. This has two consequences:
- Being stuck on the slow path cannot outlive a sync. A LAN blip mid-sync does stay on Tailscale for the rest of that sync.
- Each `status` or `dry-run` away from the LAN walks the list from the top again.

Contract-compliant tradeoff. Not a finding.

### Wrong host

Stickiness does not mask a wrong host.

- Every connection is re-verified (CA chain, `SERVER_NAME`, server-only use), so a preference grants nothing.
- A different CA or a client certificate fails the handshake and falls through. TLS 1.3 sends the client certificate only after the server's is verified, so a spoofed `.local` gets no identity.
- A spoofer can force the slow path, which is what A4 is about.
- The remaining case is a second machine holding `server.pem` or `ca.key`, such as a restored old home. It would be accepted, and list order rather than stickiness picks it. That risk predates the list and needs key material. Not a finding.

### All-or-none bind and stop

Correct.

- All binds happen before any thread spawns, and a failure drops what was bound (M6 confirms the behaviour is tested).
- `stop` sets the flag, then wakes each listener, so no accept loop can re-park after being woken. Two listeners stopped cleanly in every run.
- A failed wake would hang `join`, for example if the interface has gone. `stop()` has no production callers, though: the CLI uses `wait()`. So that exposure is test-only.
- A `UnixListener::bind` failure at `mod.rs:118` after spawning leaves accept threads running, but the process exits on that error in production. Same shape before this change.

### Serde

No defects beyond A9.

| Input | Result |
|---|---|
| Old bare `address = "h:1"` | reads unchanged |
| Bare `address = "h"` with `rsync_host` | saves as `address = "h:7750"`, legacy key dropped |
| List with `credentials` and `[as]` | round-trips, list stays inline |
| `["a:1","a:1"]` | collapses to one, written back as a string |
| `""`, `"  "`, `[""]`, `[]` | refused with a good message and caret |
| Unknown key next to `address` | `deny_unknown_fields` still names it and lists the valid keys |

`fleet.toml` writes go through `toml_edit` and never touch `listen`.

### Write-set gate

Nothing should have been touched. The diff adds no spawn, transfer or file write. `write_set_*.rs` is unchanged, and M8 shows the gate does scan the new `addresses.rs`. `install-macos.sh` is outside the gate's scope, which walks only `src/`.

### The flaky test

The new form is an improvement, and it passed 300 of 300 runs. It exercises what `poll` really reports, and the synthetic cases above it remain.

## What's Done Well

- Fallback happens only before anything is sent (`connect_any` returns before `send`), so a request can never run twice on home.
- `dial_order` is a small pure function with tests at the prefix boundaries (`febf::` dropped, `fec0::` kept).
- Binding everything before spawning anything makes all-or-none trivially correct.
- Install by rename correctly protects the running daemon's inode.
- Parsing refuses bad values with line and caret, and the empty cases are covered.
- A single address keeps its own error shape, so existing users see nothing new.
