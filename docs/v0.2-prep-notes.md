# v0.2-prep notes

Two changes to the walk/exclude layer on `bsneed/v0.2-prep`, one commit each.

## 1. Exclude engine: globset (`ee075bf`)

`src/exclude.rs` no longer hand-rolls rsync's matcher. Patterns are globset
0.4.20 globs (the version `sovran.la/filesystem` locks) built with
`literal_separator(true)`, so `*` stays inside one component as it does in
rsync. The matching rule is the filesystem crate's `WalkOptions::is_excluded`:
a pattern matches the **unit-relative path** or the **bare file name**.

**Not adopted: the absolute-path arm.** The filesystem crate also tries the
absolute path. In replicant one unit is `/Users/morgan/...` on a Mac and
`/home/morgan/...` on Linux, and rsync only sees paths below the transfer
root, so an absolute match would make the two sides and rsync disagree.

Each pattern is parsed once (`src/exclude/pattern.rs`) and both the glob and
the rsync rules are rendered from the same tokens. `Excludes::new`,
`for_root` and `push` now return `Result`; `matches`, `path_excluded`,
`push_exact` and `rsync_args` keep their signatures. fleet.toml patterns are
checked at load (`exclude::check`), so a bad pattern fails `fleet.toml`, not a
sync.

### Behaviour changes

- A pattern with an inner `/` (`agents/state`) is now **rooted at the unit**,
  as the filesystem rule makes it. It used to match at any depth (rsync's
  unanchored rule). To match at any depth, write `**/agents/state`. PLAN.md's
  example config is still valid; a one-line comment there now says this.
- The built-ins are `**/.git/**/*.lock` and `**/.git/worktrees/` (they were
  `.git/**.lock` and `.git/worktrees/`). They mean the same thing, at any depth.
- Patterns the old matcher accepted but that are now refused (see below)
  make fleet.toml fail to load. A leaf running this code against an older home
  that sends such a pattern fails at discovery. Upgrade both ends together.

### Translation table (globset → rsync)

| globset (fleet.toml) | means | rsync rule(s) |
|---|---|---|
| `target` | name, any depth | `target` |
| `*.log` | name, any depth | `*.log` |
| `build/` | directory name, any depth | `build/` |
| `/top` (internal only) | unit-relative path | `/top` |
| `agents/state` | unit-relative path | `/agents/state` |
| `a/**` | everything under `a` (not `a`) | `/a/**` |
| `**` | everything | `/**` |
| `**/x` | `x` at any depth | `/x`, `/**/x` |
| `a/**/b/` | `a/b`, `a/…/b`, directories | `/a/b/`, `/a/**/b/` |
| `**/.git/**/*.lock` | two `**/` → four rules | `/.git/*.lock`, `/**/.git/*.lock`, `/.git/**/*.lock`, `/**/.git/**/*.lock` |
| `v[0-9]` | positive ASCII class | `v[0-9]` |
| `\*lit` | literal `*` | `\*lit` |
| `we\\ird` (no wildcard) | literal `\` | `we\ird` (rsync treats `\` as an escape only when the rule has `*`, `?` or `[`) |
| `we\\ird*` | literal `\`, then `*` | `we\\ird*` |
| `\{x\}` | literal braces | `{x}` |

Why the expansion: globset's `**/` matches zero or more directories, but
openrsync's matches one or more (measured: `/a/**/b` does not exclude `a/b`).
Each `**/` therefore becomes a rule without it and a rule with it. At most
four `**/` per pattern (16 rules).

`rsync_rules_follow_the_translation_table` in `src/exclude_tests.rs` holds the
code to this table.

### Refused, and why

| Pattern | Reason |
|---|---|
| `?` | globset matches one character, rsync one **byte**: `q?` excludes `qé` in globset, not in openrsync (measured) |
| `[!a]`, `[^a]` | same character/byte split. openrsync also does not support `^` at all: `q[^a]` did not exclude `q1` (measured) |
| non-ASCII, `/`, `\`, `[` (so `[[:alpha:]]`) inside a class; `[]…]`; `-` at a class end; bad ranges | the two engines read these differently, or not at all |
| `{a,b}`, unescaped `{` `}` | alternation exists only in globset. `\{` is accepted |
| `**` inside a component (`a**`, `.git/**.lock`) | globset reads it as `*`; rsync's crosses `/` |
| `***` | rsync-only syntax |
| `//`, `\/`, trailing `\`, unterminated `[`, unmatched `]` | malformed. The old matcher treated an unterminated `[` as a literal; globset refuses it |
| empty, `/`, leading or trailing whitespace, line breaks | they name nothing, or rsync would trim or split them |
| `!`, `+ …`, `- …` | rsync reads them as filter-rule prefixes (`!` clears the list) |
| anchored `/x` in fleet.toml | still refused, as in v0.1. Used only internally by `push_exact` |

### Differential test

`src/exclude/rsync_diff_tests.rs` builds an 80-entry fixture: repeated names
at several depths, `.git` at the root and nested, a symlink to a directory,
names with `\`, `*`, a space and braces. For each pattern class (bare name,
`*.ext`, `dir/`, anchored `/x`, `a/**/b`, rooted and `**/`-prefixed slash
paths, `x/**`, classes, escapes, `**`, built-ins, `push_exact` literals, a
whole root list) it asserts that the set `path_excluded` drops equals the set
`rsync -n -a -8 --itemize-changes` leaves out given `rsync_args()`, and that it
equals a hand-written expected set. It also checks `repos::all_names`, a real
walker, against rsync. It runs against the system rsync and names the flavour
on failure. Here that is openrsync (protocol 29). As a check, breaking the
`**/` expansion makes 4 of its 6 tests fail.

## 2. Parallel discovery (`7204cbd`)

`repos::discover` now walks with `ignore::WalkBuilder::build_parallel()`
(0.4.33, as the filesystem crate locks it). Every ignore source is off
(`hidden`, `git_ignore`, `git_global`, `git_exclude`, `ignore`, `parents`,
`require_git`) and so is `follow_links`. The walk uses `state::workers()`
threads. Each thread keeps its findings and sends them down an `mpsc` channel
when it is dropped. `discover` sorts every list, as before. Code:
`src/repos/walk.rs`.

What is unchanged: repos (`.git` dir) and worktrees (`.git` file into
`.git/worktrees/`) are recorded and not descended, excludes prune
directories, non-UTF-8 names are skipped, and an unreadable directory is an
`Error::Io`. `all_names` (the case walk, which skips `.git/objects`) is still
serial; it already runs per unit inside `parallel_map`.

Tests (`src/repos/walk_tests.rs`):
- the old serial walk, kept as a reference, equals the parallel one under
  three exclude lists;
- five discoveries of an 800-file tree are identical;
- hidden files and files named in `.gitignore`, `.ignore` and `.rgignore`
  are all seen;
- deep worktrees and repo-in-repo are not descended;
- a repo under an excluded directory is not found;
- an unreadable directory is an error.

Removing the sort makes three of them fail.

### Timing

Measured on this Mac (16 cores, release build, best of 5,
`repos::discover` with `target`, `node_modules` and `.build` excluded):

| Tree | entries | serial, old matcher (`b4c057f`) | serial, globset (`ee075bf`) | parallel (`7204cbd`) |
|---|---|---|---|---|
| `/Users/morgan/work` | 161 repos, 82,016 loose | 342 ms | 333 ms | **123 ms** |
| `/Users/morgan/work/sovran.la` | 14 repos, 135 loose | — | 0.4 ms | 3.2 ms |
| `/Users/morgan/work/sovran.la/replicant` | is a repo | 0.0 ms | 0.0 ms | 0.0 ms |

On `/Users/morgan/work`, serial and parallel produce byte-identical
`Discovery`s (hashed `{:?}`, two runs each).

The home daemon still logs `snapshot for <host>: discover Xms, units Yms …` to
stderr. On the daemon test fixtures (debug build, a few files) it reads
`discover 4–7ms`, up from `0–1ms`.

## Noticed, not fixed

- **The parallel walk has a fixed cost**: about 3 ms per `discover` in release
  and 4–7 ms in debug, even on a tiny tree. Most of it is likely `ignore`'s
  idle workers waiting before they quit. The cost is paid once per
  subscription. If a host has many small subscriptions, `Discovered::run`
  could do one multi-root walk (`WalkBuilder::add`) instead of one walk each.
- **Not verified against rsync 3.** This agent had no tailscale access, so the
  differential test has only run against openrsync. The translation uses only
  what both read the same way (anchored rules, and a `**/` rule plus its
  zero-directory twin). Run `cargo test exclude::rsync_diff` on thistledown to
  confirm.
- **Pre-existing drift, now gone.**
  - Under openrsync the old unanchored built-in `.git/**.lock` matched only a
    `.git` at the transfer root: `r/.git/HEAD.lock` was not excluded.
  - The old `push_exact` escaped a `\` in a name even when the rule had no
    wildcard, so rsync matched the name literally and missed it.
  - The old `[^…]` class does nothing in openrsync.
- **Root excludes are relative to each unit.** A slash pattern therefore
  covers different paths depending on how a host's subscription is split:
  `tundra/x` matches under a `work` subscription but not under `work/tundra`.
  This was true before, and the rooted rule makes it sharper. `**/` patterns
  do not have the problem.
- **Mixed versions.** An old leaf reads `**/x` with the old matcher, which
  needs a `/` before `x`, so it misses a top-level `x`. Upgrade home and every
  leaf together.

# v0.1 review fixes

Five items from `docs/v0.1-review.md`, one commit each, regression test
first. Baseline before the first one: 260 tests, clippy and fmt clean.

## Nit: `for-each-ref` decoded strictly

`git::decode_refs` replaces the lossy decode in `git::status`. A ref name that
is not UTF-8 is an `Error::Git` naming the repo and the ref, the same shape as
the porcelain decode (`parse_porcelain_v2`), which already refused paths.

Tests (`src/git_tests.rs`): the decoder directly, and real git. APFS refuses a
non-UTF-8 file name, so `git update-ref` (with `--stdin -z`) fails here with
EILSEQ before it writes anything; a hand-written `.git/packed-refs` line gets
the byte `0xE9` through `git for-each-ref`, and `status` must refuse it. Both
tests failed against the old lossy decode.

## Q3: `refs/remotes/*` left out of the repo hash

`state::repo` hashes every `for-each-ref` line except those starting with
`refs/remotes/`. Branches, tags, `refs/stash`, HEAD and anything else (notes,
replace refs) are still hashed. The module doc records it as a decision.

For a repo with no remote-tracking refs the hashed bytes are unchanged (each
line is fed back with its `\n`), so its hash is the same as before. A repo
with remote-tracking refs hashes differently from v0.1. No production
baselines exist yet (v0.1 is read-only), so nothing is invalidated.

Test (`src/state_tests.rs`,
`remote_tracking_refs_are_not_state_but_local_refs_are`): creating, moving and
packing remote-tracking refs leaves the hash alone; creating and moving a
local branch, adding a tag, and a local branch literally named
`refs/heads/refs/remotes/x` all change it. It failed on the first
remote-tracking ref before the change.
