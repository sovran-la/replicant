# replicant v0.1.0 — implementation notes

What v0.1 assumed where PLAN.md was silent, where the code diverged from the
plan's sketch, what was measured, and what is proposed for the plan. PLAN.md
itself is unchanged.

## Assumptions (PLAN.md silent or ambiguous)

1. **Units.** The table is decided per *unit*: one per repo found under a
   subscription on *either* side (the union, so a repo that exists only on home
   is still a unit), plus one *loose* unit per subscription holding every
   non-repo entry under it. A subscription that is itself a repo has no loose
   unit. "Per non-git directory" was read as "per subscription"; finer loose
   granularity can come with v0.3's per-file conflicts.
2. **"HEAD" in the state hash means every ref.** The requirements list
   branches and stashes as state, so the repo hash covers `.git/HEAD`, all of
   `for-each-ref` (incl. `refs/stash`), and the dirty tree: every porcelain v2
   entry (which names staged content by blob id) plus the working-tree bytes of
   anything the index does not describe.
3. **Loose manifest is metadata, not content**: (path, kind, size, mtime,
   mode, link target). rsync `-a` preserves mtimes, and baselines are compared
   against the same side's next hash.
4. **Two extra table rows**: *no baseline, both populated, identical hashes →
   nothing* (otherwise the whole Syncthing cutover is a wall of conflicts) and
   *both changed to the same state → nothing*. A home marker from *another*
   leaf is its own row, *quarantined*. An *unsubscribed* baseline is a *remove*
   row (the plan's "next sync cleans it off").
5. **Baselines record both sides' hashes** (`leaf`, `home`), each compared only
   with its own side, so the table stays correct even where the hash is not
   perfectly machine-independent.
6. **Guardrail 3's `*.lock`** means git's own locks inside `.git` (not
   `.git/objects`, not `.git/worktrees`). A `Cargo.lock` is source, not a write
   in progress.
7. **Guardrail 4 applies when the leaf is macOS** (`cfg!(target_os = "macos")`),
   regardless of home's OS; home only computes collisions when asked.
8. **Built-in excludes are only `.git/**.lock` and `.git/worktrees/`.**
   `target`, `node_modules`, `bin`, `.build`, `.DS_Store` come from each root's
   `exclude` in fleet.toml, as the plan's example config lists them. Anchored
   (`/x`) patterns in fleet.toml are refused.
9. **Unsubscribing a path inside a broader subscription** carves it out with
   `[subscriptions.<host>] except = [...]`; re-subscribing restores it;
   unsubscribing a path *above* subscriptions removes all of them.
10. **Home's own home dir** is `[daemon] home_dir` (default `$HOME`); every
    root must be under it, which is what lets paths be home-dir-relative.
    `[daemon] name` (default hostname) is what leaves call home.
11. **Trust model**: per the agents pattern, home mints a CA and one bundle;
    each leaf saves it as `~/.config/replicant/home.pem`
    (`replicant config export-creds` on home). A leaf **names itself** in each
    request, so the cap guards against mistakes (the plan's threat model), not a
    hostile leaf holding the bundle. Server-side ssh confinement remains the
    hard boundary, and is not built (approve does not touch ssh keys in v0.1).
12. **Leaf config** gained `home_dir` (default `$HOME`) and `rsync_host`
    (default the home name; `"local"` = home's paths are on this filesystem,
    for same-machine runs).
13. **Journal timestamps are UTC** (`2026-10-31T19:04:11Z`); std has no time
    zone database and the journal is read from several zones.
14. **Exit codes**: `sync --dry-run` exits 2 when any unit needs a human
    (conflict, quarantine, refusal); errors exit 1.
15. **`status` does not take a queue entry**; only `sync --dry-run` does.

## Divergences from the implementation sketch

| sketch | v0.1 | why |
|---|---|---|
| `conflict.rs` | not present | prompting is v0.3 |
| `ssh.rs` | folded into `rsync.rs` | rsync's own `host:path` is the whole ssh invocation in a dry run |
| — | `units.rs` | the unit model both sides share |
| — | `plan/` | leaf orchestration of status/dry-run (decide + diff + guards) |
| — | `exclude.rs` | rsync-semantics matcher so walkers and rsync agree |
| — | `git.rs`, `record.rs`, `timefmt.rs` | git invocations; versioned per-unit JSON records; dates without a crate |
| `daemon/remote.rs` | `certs.rs` + `tls.rs` + `remote.rs` | same split as the agents crate |
| — | `daemon/{home,home_serve,leaf,local,wire,fleet}.rs` | handlers per role, wire types, `fleet_state` |
| `subscribe.rs` | home-side logic only | the leaf half is in `daemon/leaf.rs` |
| `main.rs` (clap) | `cli/` | args, renderers and the interactive approve, tested without a tty |

No shared sovran.la crate for mTLS exists; the agents pattern was copied (and
its MCP framing replaced by one JSON line per request/reply), not depended on.

## Dependencies beyond the brief's list

- `serde_json`: the wire format, records and `--json` output.
- `toml_edit`: daemon writes to fleet.toml without destroying Brandon's comments.
- `libc`: `gethostname(2)`, `flock(2)` (one daemon per directory) and resetting
  `SIGPIPE`, exactly as the agents crate uses it.
- `rustls-pemfile`, `rustls-pki-types`: bundle parsing, as in agents.
- `tempfile` (dev only).

## Dogfood timing (birchbook, release build, 2026-10-31)

Home: a second daemon on loopback, temp fleet.toml, temp root (empty). Leaf:
subscribed `/Users/morgan/work/sovran.la/replicant` only.

| run | total | leaf state hash | rsync dry run |
|---|---|---|---|
| `status` | 22 ms | 20 ms | — |
| `sync --dry-run` #1 | 52 ms | 20 ms | 29 ms |
| `sync --dry-run` #2 | 41 ms | 16 ms | 22 ms |
| `sync --dry-run` #3 | 39 ms | 16 ms | 21 ms |

Result: `push → rhome: 1 repos, 261 files changed, 0 deleted`; `target/`
excluded, `.git/index` included, the repo's `.git/index` mtime and `git
status` unchanged afterwards.

This is one repo, so it does not answer the plan's question about the whole of
`~/work`. Hashing is ~16–20 ms per repo (two git processes each), parallel over
up to 16 threads; a hundred repos would be on the order of a few hundred ms on
the leaf plus the same on home, before rsync. Two costs to watch on the real
tree: a freshly rsynced repo's stale stat cache makes `git status` rehash every
file (replicant cannot refresh it without writing `.git/index`), and
guardrail 4's case-collision walk descends every repo on home for a macOS leaf.

## Proposed changes to PLAN.md

1. **Gitignored files inside repos are invisible to the state hash.** rsync
   moves them (an `.env`, a local dataset), but a change to one does not change
   the repo's state, so it never triggers a direction. Proposal: include a
   metadata manifest of ignored-but-not-excluded files in the repo hash.
2. **`bin` as a work-root exclude** collides with repos that track `bin/`.
   Proposal: keep `bin` out of the default `exclude` or make it `bin/` only for
   known build layouts.
3. Write the two "nothing" rows (identical without baseline; both changed
   identically) and the quarantine/remove rows into the table.
4. Write the trust note (assumption 11) into "Control plane".

## Untested, and why

- **Linux.** Built and run only on macOS. Platform-specific code is limited to
  `$HOME`, `cfg!(target_os = "macos")` for guardrail 4, and openrsync vs rsync 3
  output (both formats are parse-tested; only openrsync ran).
- **rsync over ssh.** Every dry run here used `rsync_host = "local"`. The
  `host:path` form is unit-tested as arguments only; paths with spaces over ssh
  are not protected: openrsync (macOS's rsync) rejects `-s`/`--protect-args`
  (checked), so it is not passed. rsync ≥ 3.2.4 on home protects arguments by
  default; an older home would split such a path.
- **A real case-collision pair on disk.** APFS here is case-insensitive; the
  detector is tested on name lists, and the on-disk test asserts the merge
  instead.
- **Restart under load**: `one_daemon_per_directory` allows up to 5 s for the
  lock to come free, because under a parallel test run a forked child of
  another test can briefly hold a copy of the fd.
